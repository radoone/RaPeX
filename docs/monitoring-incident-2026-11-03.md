# Monitoring incident — 3 November 2026

The scheduled merchant monitoring run repeatedly failed after Gemini Developer API returned HTTP 402: its AI Studio prepaid credits were depleted. Flash, text-only and Flash Lite retries all used the same exhausted billing account. Analysis correctly remained unavailable; no failed check was recorded as safe. The first 1,800-second timeout also left a still-valid 33-minute lease, so an early task retry correctly refused to overlap it.

The matcher now calls the same Gemini 2.5 Flash / Flash Lite models through the already configured Vertex AI plugin, using the runtime service account and project billing. Identifier-first retrieval, vector thresholds, prompts, image limits, identity rules, merchant decisions and the match cache contract are unchanged. Model attempts receive an abort signal, have a 60-second limit each and share a 150-second budget per 12-candidate analysis, after media preparation. Account billing/authentication errors stop retries on the same provider. These are analysis limits, not a catalog-wide deadline or a monetary spending cap. An unavailable analysis still fails closed.

`refreshShopifyBillingEntitlements` separately lacked `SHOPIFY_PARTNER_ORG_ID` and `SHOPIFY_APP_GID`. Both non-secret identifiers were copied from the existing Shopify host through a configuration-only Functions v2 update with `serviceConfig.environmentVariables` as the explicit update mask. Existing environment values and the Partner API token secret binding were preserved. The updated scheduler revision returned HTTP 200 on a manually triggered job. The owner's installation-bound test grant remains enabled for `rozlicnytovar.myshopify.com`; normal billing enforcement for other shops is unchanged.

Each matcher consumer is released from its own deployed source and lockfile, overlaying only `safety-gate-checker.ts` and `analysis-attempts.ts`: `checkProductSafetyAPI`, `shopifyProductChangeTask`, `merchantMonitoringTask`, `runMerchantDeltaMonitoringAPI`, `merchantCatalogAuditTask`, `scanPublicShopifyStoreAPI`, and `freeScanCatalogTask`. No full Functions deployment or hosted Shopify deployment is needed. Private rollback archives, configuration snapshots and verification results live under `outputs/monitoring-incident-2026-11-03/` and must not be committed.

Validation: all 144 backend tests passed, including account-error handling, transient fallback, abort/deadline and unavailable-result tests. Every isolated bundle built against its preserved production lockfile. The deployed endpoint passed the existing 15-pair regression with zero unavailable results, including real image inputs and normal identifier/vector retrieval (`live-api-vertex.json` in the private incident directory). This fixed regression set is not an independent accuracy benchmark.

Cloud Tasks combines `maxAttempts` and a nonzero `maxRetryDuration`: a queue configured with eight attempts and 24 hours can exceed eight attempts before its time limit expires. Existing monitoring retries and leases must therefore be inspected directly; a successful API test alone does not prove recovery of the original queued run. Do not mark that run complete, advance its checkpoint or erase findings manually.

Google Cloud budgets provide notifications, not an automatic hard spending cap. This incident fix does not configure budgets or disable project billing. Actual October spend requires access to Billing Reports or an existing billing export; an estimate from token prices must not be presented as an invoice total.
